# VisionForge AI — AMD AI League

Конкурсный Qwen3-VL-2B-Instruct проверен напрямую на AMD Radeon Pro W7900D с ROCm: 10/10 основных и 7/7 дополнительных синтетических примеров. Последний прогон: запуск 16,01 с, десять CLI-вызовов 3,57 с, пик VRAM 4,790 GiB. Это не оценка скрытого набора конкурса. **GPU-прогон внутри Docker пока не выполнен; подача не готова.** Актуальные доказательства и оставшиеся гейты: `evidence/competition/readiness.md`. Локальная CPU-студия сохраняет прежний backend.

Локальный Docker-образ уже собран: `visionforge-amd:release-20261101`, image ID `sha256:e563af90646f6e8ed4b71537d4f710036d972e87d65a68d872f452ccb5655420`. Проверены базовые слои, размер, совпадение кода/модели с GPU-прогоном, offline processor и отказ без AMD GPU. Образ находится в локальном Docker; публичной registry-ссылки пока нет.

## Команды для AMD-сессии

Распакуйте архив в отдельную папку и откройте её в терминале. Нужны Linux x86-64, совместимый AMD GPU/драйвер ROCm, доступные `/dev/kfd` и `/dev/dri`, работающий Docker Engine 29.8+, Python 3.11+ с venv и интернет для сборки. Эта версия runner проверена с учётом размера Docker 29.8; старые containerd версии могли возвращать только packed size. `check.sh` отклоняет старые версии. Те же предпосылки обязательны при ручном запуске Python validator. Проверяйте на свободном выделенном GPU. Jupyter подходит только при доступе к устройствам **и** Docker daemon; само наличие ноутбука этого не гарантирует.

Полный запуск из корня пакета:

```bash
bash competition/check.sh
```

Те же шаги вручную:

```bash
python3 -m venv .competition-venv
.competition-venv/bin/python -m pip install Pillow==12.1.1
.competition-venv/bin/python -m competition.preflight --report evidence/competition/amd-preflight.json
docker pull rocm/pytorch:rocm10.0_ubuntu26.04_py3.14_pytorch_release_2.13.0@sha256:3174cb7061d94c427da96c0edef4adea28046fa3f3b2ff3948dc4e995665ff8c
docker build --pull --progress=plain -f competition/Dockerfile -t visionforge-amd:local .
.competition-venv/bin/python -m competition.validate --image visionforge-amd:local --cases data/competition/manifest.json --report evidence/competition/amd-acceptance.json
```

Validate возвращает `0` только при прохождении всех локальных гейтов, иначе `2`. Отчёт сохраняется и при недоступных предпосылках. `check.sh` сохраняет журналы сборки и проверки. Не используйте squash/flatten/export-import: это уничтожит идентичность слоёв. Не заменяйте обязательный базовый образ для обхода ошибки сборки.

В реестре базовый образ содержит около **19.08 GiB сжатых слоёв**; веса — ещё 4,255,140,312 байт. Это не измерение итогового несжатого размера. Локальный образ `visionforge-amd:release-20261101` собран; `docker inspect Size` = 59,680,730,554 байт (55,582 GiB). Docker 29.8/containerd учитывает и packed content, и unpacked snapshots: здесь это консервативная верхняя оценка, уже меньше 60 GiB, а не отдельное точное измерение unpacked size. [Методика Docker/Moby](https://github.com/moby/moby/commit/4f7f31e7b7c5296a066aae7d78b8aba4527361e0). Обеспечьте место под распакованные слои, веса и кэш Docker.

## Контракт и жизненный цикл

Штатный CMD запускает постоянный worker, загружает модель один раз и выполняет реальный прогрев. Готовность: `python3 -m competition.health`. Затем harness выполняет внутри **того же работающего контейнера**:

```bash
python3 /app/app.py --input-image /app/input/image_01.png
```

Результат: `/app/output/image_01_output.json`, структура `{"text":"..."}`. Confidence не выводится: модель не предоставляет калиброванную уверенность. CLI получает настоящую генерацию через локальный Unix socket. При ошибке возвращается ненулевой код и удаляется предыдущий ответ с тем же именем. Во время проверки сеть контейнера отключена.

**Подтверждено приложенным контрактом:** brief, стр. 5, описывает выполнение CLI внутри уже работающего контейнера; стр. 6 прямо требует загружать модель один раз. Постоянный worker со штатным CMD соответствует этой схеме. Наш validator сохраняет один контейнер для десяти вызовов. Реальный grader организаторов отдельно не запускался; его недокументированные детали не объявляются проверенными. Фактические положения PDF зафиксированы в `evidence/competition/brief-contract-20261101.json`.

Инструкция модели: номер без американских баннеров/слогана, китайский символ провинции и буква сохраняются; на знаках читаются все слова и цифры в порядке строк. Это не доказанная точность — ошибки и галлюцинации возможны. Blacklist штатов, подстановка ответов и замены O/0 не применяются. Сравнение: uppercase, удаление пробелов и `- . · _` по brief.

Декодируются PNG/JPEG/TIFF по фактическому содержимому, первый кадр TIFF, EXIF и прозрачность учитываются. Площадь ограничена 786432 пикселями с сохранением пропорций. Очень большие PNG/TIFF могут требовать много RAM при декодировании. Генерация ограничена 192 новыми токенами; ответ без EOS отклоняется как потенциально обрезанный.

Модель всегда получает полный кадр. На изображениях близкого к квадрату формата предобработка может дополнительно дать крупный вид области контрастного текста: связные компоненты тёмных/светлых пикселей, без крупных рамок и мелких точек. Такой вид не заменяет исходник: он способен пропустить слабоконтрастные строки, поэтому полный кадр остаётся обязательным, а инструкция требует учитывать обе версии без повторения текста. Широкие номера передаются целиком одним изображением. Алгоритм не содержит слов, эталонов или таблицы ответов. Результаты на синтетических изображениях не доказывают точность на фотографиях.

## GPU-прогон в конкурсном Jupyter без Docker

Распакуйте исходный пакет в отдельную папку в постоянном хранилище и выполните из его корня:

```bash
python3 -m competition.notebook_setup
```

Этот отдельный маршрут сохраняет установленный провайдером ROCm Torch и создаёт собственное окружение .amd-venv. В AMD notebook базовый Torch находится вне стандартного system-site; setup добавляет его путь в окружение до установки зависимостей и закрепляет точную версию. Проверяется сохранение ROCm до и после pip. Веса скачиваются в models/qwen3-vl-2b. Результат notebook-acceptance.json подтверждает только прямой GPU-прогон: Docker/base-layer/size гейты остаются NOT_RUN, submission_ready всегда false.

Установщик реально проверен в конкурсном Jupyter с новым окружением и уже скачанными весами: `evidence/competition/gpu-setup-20261101/`. Если Docker собран на машине без AMD, отдельно проверьте слои, размер, веса, идентичность GPU-проверенных исходников и offline processor:

```bash
python3 scripts/verify_competition_image.py --image visionforge-amd:local --gpu-report evidence/competition/gpu-release-20261101/evidence/competition/notebook-acceptance-release.json
```

Эта команда сохраняет `image-verification.json` и оставляет `amd_container_inference` как NOT_RUN. Финальный `competition.validate` на Linux AMD Docker host всё равно обязателен.

## Матрица проверки brief

| Требование | Проверка |
|---|---|
| Обязательный финальный FROM | Точный tag/digest; сравнение реальных RootFS diff-ID базового и конечного образа |
| Несжатый образ ≤60 GiB | docker image inspect, поле Size |
| Настоящий AMD GPU | torch.version.hip, доступный GPU, все параметры на cuda-устройстве ROCm; CPU/NVIDIA отклоняются |
| VRAM ≥1 и ≤48 GiB, допуск сверху 1% | Реальные параметры, allocated/reserved/peak PyTorch и отдельный sampler driver memory каждые 3 с, включая запуск; максимум ≤48.48 GiB |
| Запуск ≤600 с | От docker run до готовой прогретой модели; cold warmup получает оставшийся startup budget |
| Вызов ≤30 с | Таймер всего CLI, включая IPC и запись JSON; таймаут не выдаёт старый ответ |
| 10 изображений ≤600 с после готовности | Общий таймер включает проверки и чтение ответов |
| Одна загрузка | Постоянный worker, одинаковый PID до/после, model_loads=1 |
| Вход/выход | 10 изображений PNG/JPEG/TIFF, правильное имя JSON, строка text |
| Текст | Exact match с собственными эталонами и нормативная normalization |
| Публично доступный registry image | Отдельный ручной гейт после AMD-проверки; публикация не выполнена |

Sampler видит использование всего GPU, включая другие процессы. Выделите один свободный GPU. Трёхсекундная выборка может пропустить краткий пик, поэтому дополнительно учитывается максимум allocator. Это не подменяет измерения организаторов.

`data/competition/manifest.json` содержит **собственные синтетические** изображения: US/Chinese plates, stop/speed/warning/advisory signs, наклон, шум, блики, слабый свет, размытие. Набор проверяет контракт и даёт локальный сигнал качества, но не оценивает скрытую выборку. Эталоны и изображения исключены из Docker context. Свои десять изображений можно подать через другой manifest: поля file и expected, плоские уникальные имена, покрытие PNG/JPEG/TIFF. Контент собственных изображений CC0-1.0; файлы шрифтов не распространяются.

## Модель и зависимости

- Qwen/Qwen3-VL-2B-Instruct, Apache-2.0, revision `89644892e4d85e24eaac8bacfd4f463576704203`.
- SHA-256 весов `7de1838c87a5349b016c26a1c3f7d2bc400a3d485f95ef39a7059ffd734977a0`. Сборка и запуск проверяют содержимое.
- FP16, SDPA, одно устройство. ROCm использует штатные torch.cuda API. Torch берётся из обязательного образа.
- torchvision `0.28.0+rocm10.0.0` берётся из официального AMD index с --no-deps, сохраняя базовый torch. Qwen processor требует эту зависимость даже для изображений.
- Прямые зависимости закреплены; это не полный lock транзитивных зависимостей. При сборке выполняются pip check, проверка ROCm torch и processor-only smoke. Фактический pip freeze сохраняется в `/app/installed-requirements.txt`, smoke — `/app/processor-check.json`.
- Веса скачиваются в контейнер при сборке без токенов; runtime offline. В исходном ZIP весов нет. Сохраняйте upstream license/notice при дальнейшем распространении.

Источники (проверены 28 октября 2026): [модель](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct), [Transformers Qwen3-VL](https://huggingface.co/docs/transformers/v4.57.3/en/model_doc/qwen3_vl), [processor 4.57.6](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/models/qwen3_vl/processing_qwen3_vl.py), [ROCm PyTorch](https://rocm.docs.amd.com/projects/ai-ecosystem/en/latest/frameworks/pytorch/install.html), [AMD wheels](https://stable.repo.amd.com/rocm/whl-next/torchvision/), [HIP semantics](https://docs.pytorch.org/docs/stable/notes/hip.html). Нормативные требования взяты из пользовательского PDF, стр. 4–9.

## Перед подачей

1. Получите успешную сборку и PASS в amd-acceptance.json на реальном AMD GPU. ready_for_submission_review означает прохождение только автоматизированных локальных гейтов.
2. Проверьте независимые реальные фотографии, особенно китайские номера, баннеры и мелкий текст. Скрытая точность неизвестна.
3. Сохраните штатный CMD: brief, стр. 5–6, предусматривает уже работающий контейнер и одну загрузку модели.
4. После разрешённой публикации зафиксируйте финальный digest, проверьте анонимный pull с чистой машины и повторите проверку по digest. Это ещё не выполнено. Не рекламируйте ссылку на конкурсный образ публично.

Acceptance report содержит эталоны и распознанный текст; проверяйте его перед публикацией личных данных. Validate удаляет только собственный контейнер; --keep-container сохраняет его для отладки. Для отката используйте предыдущий проверенный digest и повторите smoke; CPU-студия запускается прежним start.ps1.
